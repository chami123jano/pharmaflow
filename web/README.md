# PharmaFlow — website

The read-mostly companion to the till. It reads the cloud mirror, so it keeps
answering when the shop PC is switched off — which is the whole reason it
exists.

## What it can and cannot do

| | |
|---|---|
| Owner | Today's takings, reports, products (add and edit), stock |
| Staff | Products and stock only. No takings, no reports, no profit |
| Nobody | Everything. A signed-out visitor sees nothing, by policy |

**Stock is never written from here.** It moves only as a delta from the till,
so a sale at the counter and a delivery entered from a phone both land instead
of one overwriting the other. The product editor deliberately has no stock box.

An edit made here is written to `sync_events` *before* the mirror row, so if
only one of the two succeeds it is the one the till will pick up. The other
order would show an edit the till never heard about, and the till's next
snapshot would quietly undo it.

## Running it

```bash
npm install
npm run dev      # http://localhost:5174
npm run build    # -> dist/, a plain static site
```

`.env` holds the project URL and the **publishable** key. Both are public: the
key is compiled into the JavaScript and is meant to be readable. Row level
security is what guards the data — verified by test, a request holding only
that key gets back nothing from any table. The **secret / service_role** key
belongs on the shop PC and must never appear here.

## First run

The database must exist and someone must own it:

1. `supabase/schema.sql` in the SQL editor — creates the tables and policies.
2. Authentication → Users → **Add user** — your email and a password.
3. `supabase/make-owner.sql`, with your address filled in.

Without step 3 a login works but sees nothing, and the site says so rather than
showing empty screens.

In Authentication → Providers, turn **public sign-ups off**. Otherwise strangers
can create accounts. They would still see nothing without a role, but there is
no reason to let them in the door.

## On a phone

`manifest.webmanifest` makes it installable: Share -> Add to Home Screen on
iOS, or the install prompt on Android. It then opens without browser chrome and
looks like an app. There is no service worker and no offline cache — a stale
cached figure for takings would be worse than an honest "no connection".

## Deploying

Cloudflare Workers, free tier. `wrangler.jsonc` declares the built `dist/` as
static assets with no Worker code, so a request that matches a file is served
from the edge without running anything.

In the dashboard, **Workers & Pages -> Create -> Import a repository**:

| Setting | Value |
|---|---|
| Root directory | `web` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Environment variables | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_SHOP_NAME` |

The variables are read **at build time**, not run time, so changing one needs a
rebuild rather than a restart. A missing Supabase variable fails the build on
purpose: a site that cannot reach its data should not publish.

`wrangler.jsonc` names the Worker `pharmaflow`, deliberately generic. A
particular shop overrides it without touching the repo:

```
npx wrangler deploy --name my-shop
```

The build emits two files Cloudflare reads:

- `_redirects` sends every path to `index.html`, so a refresh or a shared link
  never 404s.
- `_headers` is generated by `scripts/headers.mjs`, because the
  Content-Security-Policy has to name the Supabase project and that is only
  known from the environment. Hardcoding it would break the site silently the
  day the project changes. The policy allows the API over https and realtime
  over wss and nothing else; verified by loading the built site under it with
  zero violations.
